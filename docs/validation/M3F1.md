# M3f1 measured evidence

This record owns observed map-scale comparisons, safety tests, sanitizer results
and host measurements. [COMPATIBILITY](../COMPATIBILITY.md#map-scale-profile) owns
supported limits, [M3F1_REFERENCE](../M3F1_REFERENCE.md) owns source investigation,
[STATE_FORMAT](../STATE_FORMAT.md) owns DSIM, and [TESTING](../TESTING.md) owns
commands. GitHub owns exact review heads, merge records and completed CI runs.
These are bounded fixture observations, not full original-map/game compatibility.

## Genuine original-C comparisons

The [provenance](../../tests/reference/m3f1_provenance.json) records source and
adapter SHA-256s, extracted functions, compiler/flags, ABI assumptions and output
hashes. Forty genuine bodies are compiled, plus original fixed/RNG translation
units. This is a compiled inventory, not a claim that every function or branch
executes. In particular, compiled player/sliding dependencies are not admitted.
The synthetic named-field adapter, terminal state and fixture initialization are
explicit projections; the whole original loader and complete actor ABI are excluded.

All twenty-nine public classic fixtures are actually exercised by thirty-three
movement scripts, destination probes, BSP/opening tables and sight pairs. Fixtures
include 128/129/256/1,024 lines, 128/129/256 sectors, sparse/dense lists, duplicates,
shared offsets, shared suffixes, nonzero floors, 24/25-unit boundaries, high-sector
REJECT bits and a dense setup at the prepared-reference budget. A closed 256-sector
strip has 769 lines; the maximum-reference fixture has 512 lines and 512 cells.
All original source files remain behavioral reference, unchanged.

## Independent canonical-state evidence

The [independent encoder](../../tools/reference/m3f1_snapshot_goldens.py) supplies
**768 C-derived DSIM-v18 captures and 64 complete byte fixtures**. Its
[provenance](../../tests/reference/m3f1_snapshot_provenance.json) hashes inputs and
outputs. Expectations use C traces, public setup bytes and documented schema,
never Rust output. All per-tic digests and all complete bytes match Rust; full
fixtures diagnose the first differing named field. The two-actor ordering script
is explicitly excluded from this encoder and remains a direct C comparison.

DSIM-v18 is the untyped static-sector field layout under a new explicit tag, not
an original savegame or demo. Earlier v1–v17 schema meanings, encoders, fixtures,
helpers and reference outputs are preserved.

The asserted `map_scale` example checks original ordering, movement through sectors,
independent first/final full bytes and repeatability. It also admits the line
capacity fixture. Debug/release output agrees; final digest:
`346f7c3e93d14e5c`. No commercial data or presentation device is required.

## Rust-specific safety policies

Focused [policy tests](../../crates/doom-sim/tests/m3f1_policies.rs) cover old/new
boundaries and rejection above them, exact/exhausted reference budgets, dense
shared/suffix lists, raw-word/cell/sight expansion limits, malformed references,
map specials, arithmetic bounds including BLOCKMAP origin, zero/full actor capacity,
invalid controls, pending retirement, generation reuse, unsupported player/combat/
AI/map-spawn APIs, independent instances, pause and presentation reads. A late
actor outside the next-step margin rejects before any earlier actor moves.
These are recoverable-error contracts, not claims that unsafe C inputs reject in
the same way. General user thinker budgets retain their separate historical contract.

## Fuzzing and AddressSanitizer

All seventeen fuzz targets build with ASan. The new map-scale campaign completed
**4,096 actual executions in 74.37 seconds, with no findings**, using libFuzzer
seed1, twenty-two synthetic corpus seeds, inputs at most35 bytes, eight operations,
at most eight tics and four actor slots. Inputs select dense/sparse/shared large
fixtures, malformed references, large sector tables, origin/coordinate changes,
sight-work DAGs and exhausted budgets; operations cover controls, movement/sight,
spawn/retirement, stale IDs, unsupported buttons, atomicity and two-instance equality.

Per-input timeout was20 seconds and RSS limit2048 MiB. AddressSanitizer was enabled;
`ASAN_OPTIONS=detect_leaks=0` disabled leak detection. **No LeakSanitizer coverage is
claimed.** This bounded campaign is neither exhaustive nor original-C branch coverage.
Corpus/artifact paths are local development details and are not published here.

## Host performance and memory

[Raw three-sample measurements](m3f1-measurements.json) were collected on Linux
x86_64, rustc1.99.1, optimized release builds. The measured command and native
`wait4` launcher are in [the measurement tool](../../tools/measure_map_scale.py).
There is no invented throughput target or CI performance threshold.

Each separate process measures100 complete simulation preparations **excluding
parsing**,1,000 immutable collision queries,1,000 sight queries where admitted,
and100 tics including snapshots. Peak RSS includes the Rust process, parsing,
fixture pages, snapshots and allocator effects. A small native launcher avoids
including Python's pre-exec resident pages. Prepared storage is actual requested
vector capacity for compiled lines/lists, leaf sectors and runtime sector heights;
it excludes parsed Map, actors, snapshot caches and allocator overhead.

Medians of three samples; timing columns are total microseconds for the operation
counts above. RSS is KiB, prepared storage is bytes. Legacy3 does not admit sight.

work. More sectors increase snapshot work even when empty. Preparation and storage
remain bounded; query deduplication uses fixed bounded stack scratch and first
encounters retain source order. Small timing differences and host RSS variation
are observations, not universal speed or allocator guarantees.

## Regression, documentation and preservation

Mandatory local checks passed: workspace build, workspace/fuzz formatting,
warnings-denied Clippy and rustdoc, **296 workspace tests, 296 Rust1.85.0 tests**
(two private opt-ins ignored), **272 release tests**, all eighteen source/independent-
encoder pairs and all eighteen asserted debug/release examples. README build/test
and map-parser commands also passed. The documentation checker resolved56 Markdown
files,536 relative links and22 anchors and verified all twenty archive digests.
Exact-head platform results belong to the PR/Actions, rather than a duplicated
live status table here. Source comparisons, independent encoding and Rust safety
observations remain distinct.

The first reference sweep detected the historical M3d3j generator's whole-directory
`generate*.py` hash inventory. The new unrelated generator was renamed
`m3f1_reference.py`, and its dedicated checks remain mandatory. The unchanged
historical generator/encoder and both new checks then passed; no old helper or
expected hash was edited. The other historical pairs had already passed in the
same validation sweep.
The source/fixture integrity check protects all165 original upstream files and
all pre-existing reference/tool/support bytes; the twenty historical document
archives retain their exact digests. No private repositories, commercial IWADs,
private cloud resources or credentials were accessed.

Documentation keeps one authoritative home per category. ROADMAP distinguishes
merged foundations from this feature's owner-review gate and broader planned work;
COMPATIBILITY matches admission; README stays concise with its visible machine-
maintained/human-directed disclosure. No full player/Demon/game, dynamic sectors,
map-special, extended-format, rendering or vanilla-demo support is claimed.
