The 26-field actor projection includes state/timer, physical/lifecycle fields,
target identity and a repeated RNG-index observation. Instrumentation rows can
represent several observations of one action; they are not unique events or
branch counts, and are not each compared one-to-one by the actor-field reader.
The independent encoder reconstructs complete ordered event fields from these
rows; Rust compares those bytes for every capture, including collision candidates,
openings, full sight visits and AI actions. This is separate from whole-snapshot
digests and sampled full snapshots. Raw C draws are replayed against the source
LUT and reconciled with Rust RNG indexes and action events; this is not a complete
separately emitted transcript of every Rust internal lookup.

Streaming [source counts](../../tools/reference/summarize_m3f3.py) additionally
identify **855,632 ordered line candidates**, **5,232 thing candidates** and
**162,233 full ordered sight visit records**. Seg entries are included in those
full visits and are not additional unique observations. The additional adapter
asserts execution of real opening and slope-clipping records; its observed native
Demon cell reaches **4,107** in an **8,192-cell** grid. The DAG case executes the
source's full **16,382-unit** traversal with typed actors.

Inputs execute one/four-owner spawning, skill filtering, nomonsters, ambush/noise,
raw stand timing, nested wake/Chase, actual multi-sector movement, repeated-frame
run actions, melee, shared-target lethal/ignored strikes, nonlethal pain/no-pain,
source/inflictor/self damage, native lethal credit, death/corpses, retirement/reuse,
RNG wrap, negative/positive floors, 24/25-unit steps/dropoffs, ordered sparse/dense
lists, REJECT and BSP. They include 1,024 lines; 256-sector/769-line maps; a map
spanning ±2,048 with a Demon moving −900 to +880; non-cardinal rays through a
changed opening; a closed opening; and actual typed high-cell access.

The C adapter uses real original structs/metadata/state tables, named-field
geometry/sector-line/seg setup, native136/state aliases, and unbound135 roster
bodies without player pointers. Original THING resolution precedes adaptation;
unadapted type12 spawn is compared separately. Full P_SetupLevel/P_GroupLines,
real player initialization and complete Demon admission are not established.
Retired C bytes are retained until reset to make the identity projection explicit.
Unsupported callbacks abort.

GNU89, 32-bit int/fixed/angle, 16-bit short, 64-bit pointers, little-endian inputs,
explicit evaluation order and recorded signed-shift/BAM adapters remain assumptions.
The inherited A_Chase direction shift is explicitly unsigned in the adapter;
negative spawn shifts use equivalent representable multiplication. These are not
unmodified portable ISO-C claims. Both admitted datasets pass the additional
signed-overflow/division/float-cast audit with identical output after removing
`-fwrapv`; shift UB and exhaustive branches are not claimed covered.

## Original source failures and Rust safety policies

A positive-180-degree THING exposes the original signed expression
`ANG45 * (mthing->angle/45)`: the strict probe reports `4 * 536870912` overflow at
original p_mobj.c line 794. The probe copies that exact expression, not a full
post-failure spawn result. Profile 20 rejects selected angle quotients outside
`[-4,3]` before any batch mutation. Older profiles keep their recorded contracts.

The source `INT_MIN` intercept followed by undefined `abs(INT_MIN)` clipping is
also excluded. Direct and nested AI queries return structured errors. Tests
inject the fractional boundary observer into native fixture records; this is
Rust safety evidence, not an invented original-C full-sight result. One fault
occurs after an earlier eligible owner would consume RNG/move, and the entire
canonical state remains unchanged.

Fifteen focused policy tests cover historical isolation, angle/filter precedence,
capacity/statistics overflow, late invalid state, pending/stale/reused identities,
invalid sector/spatial association, coordinates/controls, owner ordering, modes,
registry/action rejection, clipping, sight budgets, pause/read independence and
restart RNG. Full source comparisons separately demonstrate accepted lifecycle,
statistics and sequential shared-target behavior. Bounded plans borrow the large
world and copy only the small actor projection; no full Simulation clone per tic.

## Independent DSIM-v20 and example

Main: **2,733 C-derived captures**, 145 complete C-derived bytes and two separately
specified Rust-only capacity states. Additional: **213 C-derived captures** and
six complete C-derived bytes. Combined: **2,946 captures / 151 complete C-derived

FNV digest and complete ordered event-field bytes with named-field/first-byte
divergence diagnostics; sampled full streams provide first-named-field diagnostics.
Event projections are not counted as complete DSIM snapshots. Event counts include
the explicit Rust phase/identity projection, not only unique original C actions. Expected values
come from C rows, public bytes, schema and explicit fixture projection, never Rust.

The asserted `demon_expanded_map` example compares C fields/events and independent
bytes/digests in repeated instances. It executes the full DAG, wide-map lifecycle
and a long 256-sector sequence through pursuit, strike, pain, death and corpse.
Source motion can skip several one-unit sectors per move; it does not claim to
occupy every sector. One known C hit has pain and the wide-map hit has none.
Its final independent digest is **`f01e351a96e686c1`**. DSIM is a diagnostic format,
not a vanilla demo or savegame.

## Fuzzing and sanitizers

All **19 fuzz targets** build with AddressSanitizer. The new target completed
**4,096 actual executions in 1,953.87 seconds**, starting from **55 public synthetic
seeds**, deterministic seed 1, maximum input 35 bytes/eight operations/64 tic calls
per instance, configured slot capacity at most 64, timeout 20 seconds and RSS limit
2,048 MiB. Corpus mutations remain local/ignored. Two instances and complete-state
rejection assertions run throughout. The 39-script main catalog supplies inputs;
the three additional source scenarios are not claimed initial fuzz corpus coverage.

The MIN seed exercises read-only rejection with unbound bodies; nested native AI
rejection is a separate injected Rust policy test. No Rust ASan findings occurred.
`ASAN_OPTIONS=detect_leaks=0`: **no LeakSanitizer coverage**. The expected original-C
angle failure is a separate C arithmetic finding; it is not a Rust ASan finding.
This campaign is bounded and does not establish exhaustive branch coverage.

## Memory and performance

[Raw samples](m3f3-measurements.json) record three separate Linux x86_64 release
processes for each of nine source-backed inputs/profile selections, using rustc
1.99.1. Timers separate parsing, full construction, THING batches, collision/sight,
direct Chase, script stepping/Snapshot construction and canonical encoding.
`wait4` peak RSS includes Rust process/allocator/benchmark/event overhead, excluding
Python's launch pages; prepared bytes are a different, narrower capacity measure.
Timing loops are measurements, not additional C comparison captures.

| Selected workload | Median observation |
| --- | --- |
| Same small input, profiles 17/20 | 100 script updates: 13,980 / 14,635 µs; peak RSS 3,428 / 3,428 KiB |
| Same small input, direct Chase | 100 fresh-input calls: 5,611 / 17,006 µs; additional planning/preflight work is visible |
| 769 lines / 256 sectors, profile 20 | 100 script updates 24,661 µs; prepared 42,740 bytes / 6,152 refs |
| Four owners, larger map | 100 updates 61,981 µs; peak RSS 4,088 KiB |
| Wide map, 136 cells | 242,676 prepared bytes / 104,584 refs; peak RSS 4,316 KiB |
| 8,192-cell typed map | 344,612 prepared bytes / 58,880 refs; peak RSS 6,132 KiB |
| Full DAG sight | 1,000 queries: 82,598 µs; 16,384,000 diagnostic visits, including non-work side records |

Only the same small input under 17/20 is a direct gameplay comparison. Profile 19
unbound runs have neither typed spawning nor Chase; zero timers there mean those
operations were absent, not instantaneous. Historical Profile 17 prepared-capacity metrics
are unavailable/null. Other sizes, actors, script actions and observation volumes
differ. The shared host and three samples do not justify universal performance
or causal speed claims. No performance threshold was invented.
