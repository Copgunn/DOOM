# M3f4 validation observations

Observed on GNU/Linux x86_64 with Rust stable 1.99.1, Rust 1.85.0,
nightly 1.101.0 (2026-10-29), cargo-fuzz 0.13.2 and GCC 14.2.0.
[Source investigation](../M3F4_REFERENCE.md), [identity mapping](../ACTOR_IDENTITIES.md)
and [commands](../TESTING.md#original-actorstate-identity-metadata) define scope and reproduction.
Exact branch commits, baseline merge verification and platform CI belong to the
GitHub PR/Actions record, not a duplicate live status ledger here.

## Implementation and independent identity evidence

Complete pristine original metadata is represented: 137 actor types, 967 states,
138 sprites and associations with 74 non-NULL action symbols. This adds no
executable actor closure, profile, persistent actor field, resource capacity or
DSIM schema. It reuses the existing static source tables and typed owner services.
Canonical IDs have private bounded storage; explicit registry conversions compare
one full record at the original ordinal. They do not certify downstream registry
records or game context. Native type136/state aliases remain explicit adaptations.

The independent DOOM-IDENTITY-v1 C capture contains 1,242 records. Rust compares
all enum ordinals/names, all 3,151 actor-property fields, all 6,769 state fields
(including symbolic actions), and all 138 sprite resource names. Typed named
views, state references and forward/reverse registry round trips are checked too;
these overlapping checks are not additional unique C observations. The observer
compiles untouched info.c/h, evaluates actual enum symbols and initializer values,
and uses correctly typed printf arguments for original long fields. Aborting
callback stubs identify pointers by symbol; no action-body execution is claimed.
Source/generator/output hashes and compiler flags are in
[provenance](../../tests/reference/m3f4_provenance.json).

Six focused tests passed. Separately labeled Rust policy checks cover all 196,608
u16 candidates across the three identity namespaces, signed extremes, NUM*
sentinels, wrong names, all actor-property mutations, state-field mutations,
renamed/reordered records and native fixture aliases. Recognized MT_SERGEANT
metadata still fails unsupported execution before mutation. Canonical MT_TFOG
resolution drives existing typed spawn/state-entry services with unchanged
snapshots and retirement. Another test inserts identity queries into an existing
80-tic sequence and compares every independent DSIM-v4 digest, as well as the
unchanged control simulation. A compile-fail doctest verifies namespace separation.

## Sanitizers and bounded fuzzing

All 20 fuzz target executables were built with ASan. The new original_identity
target completed 4,096 actual executions from 22 fresh synthetic seeds, seed 1,
max_len 68, timeout 20 seconds/input and RSS limit 2,048 MiB. LibFuzzer reported
one second, final cov 165 / ft 245, corpus 34 / 215 bytes and RSS 303 MiB. No
findings occurred. These instrumentation counters are not function/branch coverage.
The target checks bounded descriptors, numeric/name/registry round trips, native
mismatches and property mutations. It does not fuzz new gameplay because none is
admitted. Existing gameplay fuzz targets were rebuilt, not each recampaigned.

The full metadata observer passed ASan/UBSan with output identical to its ordinary
compiled-C output. Both C sanitization and the Rust campaign used
`ASAN_OPTIONS=detect_leaks=0`. An initial prototype with default leak detection
failed because LeakSanitizer cannot operate under the environment's tracing setup;
it was rerun successfully with leak detection disabled. There is no LeakSanitizer
coverage, no exhaustive input coverage and no new callback-behavior proof.

## Preservation and documentation

All 165 upstream files matched their original Git blobs. All 5,663 inventoried
historical evidence/support/tool/archive/source-table paths matched the base;
existing helper and fixture paths were retained. Both lockfiles, attribution,
LICENSE.TXT and README.TXT were unchanged. Git integrity and ancestry checks
passed. The two asset-gated tests remain ignored; no commercial assets, private
repositories, UZDoom code or unrelated frameworks were accessed or imported.
The repository remains public and GPL-2.0-only. Evolving identity fuzz data is
ignored and reproducible from its synthetic seed recipe.

Human editorial review checked descriptor units, shared-state ownership, initial
versus Fast-mutated source tables, metadata versus execution, local-record versus
closure validation, sentinels, source versus Rust action ordering, historical
schema preservation and evidence qualifications. Link/anchor/archive checks
passed; the final check count is recorded with delivery in the PR.

## Remaining boundary and next recommendation

All original identities are represented, but this milestone admits no new gameplay.
Full original Demon/Spectre, real player gameplay, generalized infighting,
Fast/Nightmare/respawn, resurrection, moving sectors, hitscan expansion, rendering,
Vulkan, PK3 and ZScript remain outside scope. Recommend a separate narrowly scoped
MT_SERGEANT canonical execution-profile investigation, auditing role/type tests
and independent schema projection while retaining player/raise/Spectre exclusions.
This is future work, not a compatibility result.
