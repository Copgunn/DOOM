# M3f5 validation observations

Observed on GNU/Linux x86_64 with stable Rust 1.99.1, Rust 1.85.0,
nightly 1.101.0 (2026-10-29), cargo-fuzz 0.13.2 and GCC 14.2.0.
[Investigation](../M3F5_REFERENCE.md), [identity mapping](../ACTOR_IDENTITIES.md#canonical-demon-execution-binding)
and [commands](../TESTING.md#canonical-demon-execution-binding) define scope.
GitHub owns exact reviewed commits, merge ancestry and platform CI; these local
observations do not replace final-head CI.

## Implementation boundary

This is the smallest complete canonical-to-execution integration over the existing
Profile 20 services. MT_SERGEANT 12 / DoomEd 3002 is the Demon/Pinky. Its normal
SARG 475–495 closure maps bijectively to the existing native states. The borrowed
binding checks full source records and all projected runtime records, while the
existing constructor checks the rest of its exact registry. Canonical spawn and
state requests reuse existing batch/state/lifecycle services. The map-context
registry now derives its native definitions from canonical records with exactly
its previous output. Ordinary simulation execution gains no per-tic lookup.

Already implemented behavior remains stand/run, perception/hearing, pursuit,
melee, pain/damage, death/Fall, persistent corpses, ordered ownership and bounded
kill totals. Newly validated coverage is their connection to pristine original
Demon definitions throughout a separate C execution, plus explicit canonical
requests/observations and rejection boundaries. It is not new monster gameplay.

Raw ActorLife and DSIM retain type 136/state aliases. Canonical queries explicitly
observe source definition identity through a checked projection. M3f4 same-record
resolution still rejects native 136. Raise 496–501 remains source metadata; native
raise is 0 and no entry binding exists. No Profile21, DSIM version, actor field,
capacity increase, dependency or new scheduler is introduced. A raw-ID migration
would cross ownership/role/state policies and diagnostic identity bytes; it is a
separate, broader representation change, unnecessary for this verified binding.

adaptation. Genuine source bodies execute type 12 and original state references
throughout. The explicit target 135/roster, GNU arithmetic, source instrumentation
and synthetic geometry adapters remain documented. Seventy compiled original
bodies and two setup fragments are inherited, not new function/branch coverage.

## Sanitizers and bounded fuzzing

All 21 fuzz executables built with AddressSanitizer, including canonical_demon.
Only the new target was campaigned in this milestone; the other 20 were rebuilt,
not individually recampaigned. The new campaign completed 4,096 actual executions
from 22 fresh public synthetic seeds, seed 1, max_len 35, timeout 20 seconds/input,
RSS limit 2,048 MiB. LibFuzzer reported 552 seconds, cov 4871 / ft 12548, final corpus
284 inputs/7,982 bytes and RSS 629 MiB, with no findings. Instrumentation counters
are not exhaustive function/branch coverage. Inputs use the new maps/options and
bounded target setups with default initial RNG, capacity variations and at most
eight canonical/legacy operations per instance; the separate C test supplies the
exact scripted seeds/discards. Every failed operation preserves its complete
snapshot, and two instances compare after each operation.

The new full C dataset passed both strict signed-overflow/division/float-cast
instrumentation and ASan/UBSan; each emitted the same CSV/binary observations as
the ordinary build. The unchanged M3f4 metadata observer also passed its sanitized
check. Inherited GNU ABI, explicit evaluation-order/direction-shift arithmetic
adapters and bounded source-defined angles remain qualifications; this is not a
claim of arbitrary portable unmodified ISO C execution.

Both the C address checks and Rust campaign used ASAN_OPTIONS=detect_leaks=0.
The managed tracing environment does not support the established leak-detection
configuration. No leak campaign succeeded or is claimed. Bounded campaigns are
not exhaustive safety or compatibility proof.

## Remaining boundary and recommendation

This establishes canonical definition requests and source-derived metadata for the
already supported execution slice. It does not migrate raw runtime identities or
admit full Demon/Spectre, Shotgun Guy/hitscan, real players, generalized infighting,
Fast/Nightmare/respawn, resurrection, dynamic sectors, general projectiles,
rendering/Vulkan, PK3 or ZScript. Geometry/actor/ownership bounds remain frozen.
Recommend a separate narrowly scoped original-ID storage migration investigation,
starting with an inventory of every role/state guard and an independent versioned
DSIM plan, before changing raw actor/state representation. No such migration is
part of this milestone or authorized automatically by this recommendation.
