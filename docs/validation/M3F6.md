# M3f6 validation observations

This record owns local observations for the runtime identity investigation.
[Source audit/design](../M3F6_REFERENCE.md),
[mapping](../ACTOR_IDENTITIES.md#native-runtime-identity-boundary) and
[commands](../TESTING.md#native-runtime-identity-boundary) define the boundary.
Exact feature heads, merge ancestry and final cross-platform CI belong in GitHub.

## Implemented boundary

The complete consumer audit found that native136 is reused across unrelated
fixture profiles, source136 is MT_MISC86, and native1–21 replace original weapon
metadata. An in-place original-ID substitution would break owner/COUNTKILL proofs,
state-entry and raise-root admission, public ActorLife/event values, cached registry
metadata and DSIM-v20. A future opt-in profile with a source registry and independently
versioned serialization can address these boundaries. It is not implemented here.

The selected narrower outcome preserves native storage and adds sealed native
execution views through the existing borrowed definition proof. The old canonical
query delegates through that explicit boundary. One mapping supplies the checked
reverse lookup; Profile20 entry/death/Fall guards classify named canonical states.
Earlier profiles retain their fixture policies. No persistent actor field, duplicated
identity, capacity, scheduler, gameplay, profile or DSIM version is added.

## Independent evidence and historical interpretation

The new boundary test reuses immutable M3f5 genuine-C observations and independent
encodings. It checks 1,906 gameplay type/state fields and 26 separate raw-spawn
identity fields against the new view, while also asserting actual native ActorLife
slots. All 21 normal source states occur. It rechecks 664 existing C-derived captures
and 14,063 ordered event fields, including 55 full byte fixtures. These are reused
observations, not additional unique captures, C inputs, functions or branches.
The view projects original identity; raw Rust storage still uses native aliases.

The complete M3f5 comparison remains the authority for 93,834 actor fields, 786
recorded gameplay/setup draws, 2,656 statistics fields and separate raw-spawn
338 actor fields/279 draws/65 spawnpoint fields. Actual Rust RNG indices and
outcomes are compared; no independent log of every internal Rust draw is claimed.
M3f4 retains all 137 actor, 967 state and 138 sprite metadata records and ordering.

Historical M3f3 evidence remains 2,946 C-derived captures, 151 C-derived full fixtures,
two separate Rust-policy fixtures and 42,992 ordered event fields. All existing
Profiles 1–20, role/resource/arithmetic restrictions and DSIM interpretations remain.
No historical capture/helper/encoder is rewritten or regenerated to fit Rust.

## Focused Rust policies

Five integration policies exhaust every u16 native type/state candidate, all
canonical identities against the explicit closure, number collisions, source versus
native entry restrictions, query purity and two-instance historical replay, pending/
stale/reused handles and wrong profiles. Two private tests inject canonical numbers
into native storage and check complete-state rejection, and exhaustively verify the
named entry/death/pre-Fall classification against the frozen native guard policy.
These seven policies are separate from the one independent-C boundary test.

## Sanitizers and bounded campaigns

All 22 fuzz executables built with AddressSanitizer. Only runtime_identity was
campaigned for M3f6; the other targets were rebuilt, not individually recampaigned.
The model uses two instances, the nine public fixture cases/options with default
initial RNG, capacity variants, and at most eight native/canonical/lifecycle
operations per instance. It checks representation consistency, rejected-operation
atomicity and replay. Scripted C fixtures separately cover their recorded RNG
seeds/discards. Bounded fuzzing does not establish exhaustive coverage.

A pre-inline campaign completed 4,096 executions from 24 fresh synthetic seeds in
609 seconds, cov 4985 / ft 13052, final corpus 301 inputs/8,743 bytes, RSS 616 MiB,
with no findings. A preliminary run was interrupted for a checked-conversion
cleanup and is not a completed campaign. The final-source campaign after the
inlining adjustment is reported separately below; prior results are not relabeled
as final-source validation. Inputs use seed 1, max_len 35, timeout 20 seconds and
RSS limit 2,048 MiB. Counter values are instrumentation observations, not function
or branch coverage claims.

Both Rust campaigns and C address checks use ASAN_OPTIONS=detect_leaks=0.
LeakSanitizer remains unsupported in the tracing environment; no leak-detection
campaign succeeded or is claimed. The C arithmetic audit retains its documented
GNU ABI, signed-shift/evaluation-order adapters and bounded-angle qualifications.

The final-source campaign completed **4,096 executions in 594 seconds** from a
fresh 24-input/688-byte seed corpus: cov 5029 / ft 13280, final corpus 301 inputs /
8,652 bytes, RSS 613 MiB, with no findings. All 22 final-source ASan executables
were rebuilt. It is separate from the completed pre-inline campaign above.

## Matched performance and memory observations

The unchanged legacy and canonical-API tools ran on clean post-M3f5 master and
this feature using Rust 1.99.1 release settings and identical inputs. Local
validation/fuzzing was idle during every measurement batch. Every median uses
three separate processes. Workload/profile IDs, geometry/resource counts, query
counts and snapshot byte counts match across all batches. No storage migration
or new workload is introduced; the existing canonical API calls the new native
view through delegation. Each row is compared only to itself; different profiles
and geometry/observation volumes are not equivalent workloads.

CPU affinity/frequency, thermals and external host contention were not controlled.
Repeated baseline medians themselves varied; three samples do not establish a

limitation, not hidden by choosing the repeat. No performance threshold was used.

Native identity views add no per-actor field or heap allocation by code inspection;
the new reverse lookup is a bounded immutable table. NativeDemonState measured
the same two-byte scalar size as StateId; NativeDemonType is zero-sized. No global
allocation-count instrumentation was performed. Native wait4 peak RSS includes
code, allocator and diagnostic overhead, and is not an isolated actor-memory metric.

## Unsupported behavior and next recommendation

No runtime ID becomes canonical in storage. Native136/state aliases and unbound
target135 remain; historical other-profile uses of those numbers retain their
separate definitions. No original-ID DSIM-v21, new profile or new actor/state
execution is admitted. Spectre, Shotgun Guy/hitscan expansion, real players,
generalized infighting, Fast/Nightmare/respawn, raise/resurrection, dynamic sectors,
general projectiles, rendering/Vulkan, PK3 and ZScript remain outside this milestone.

Recommend a narrowly scoped independent original-ID registry/profile and diagnostic
format contract for the existing Demon closure, proving old/new interpretation
against immutable C observations before changing raw runtime fields. This is a
future prerequisite, not a completed migration or additional gameplay admission.
