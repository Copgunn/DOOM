## Implemented scope

The opt-in registry retains all 137 actor, 967 state and 138 sprite identities with
pristine original records. Definition keys distinguish original actors from the
synthetic context body, whose appended slot derives from original count. Source
135/136 remain decorations. Only the existing Demon/effect/context closure executes;
Demon ActorLife actually stores type 12 and source states 475–495. State policies
derive from original roots/next/actions; direct entry remains restricted, pain/death
are damage-controlled and raise is excluded. Existing movement, AI, damage, actor
ownership, checked planning and scheduling execute the closure. No second engine,
persistent duplicate IDs, live-capacity/geometry expansion or new gameplay is added.

DSIM-v21 carries actual source/context IDs, independent execution-policy ID 1 and
immutable registry/context schema identifiers. It omits redundant registry rows,
retaining complete dynamic/map/event fields. Bounded Result encoding and read-only
v20/v21 decoding reject namespace/schema/framing/resource errors. V20's full metadata
and native interpretation remain intact; v20-only reading rejects21. Decoder
acceptance does not certify arbitrary physical state, full-field shape or safe
world restoration. Non-identity event payloads remain opaque.

## Sanitizers and bounded fuzzing

C checks used GCC 14.2.0; runtime fuzzing used nightly 1.101.0 with cargo-fuzz 0.13.2.
All 24 ASan targets were built; only the two new targets were executed for M3f7.
`ASAN_OPTIONS=detect_leaks=0` applied to both C and Rust campaigns. Leak detection
is unsupported in this tracing environment: no leak coverage is claimed.

Each new target completed two fresh 4096-execution batches, before and after the
construction-only allocation cleanup: 8192 executions per target in total. The
final batches rebuilt all 24 targets from the final runtime source. Seed1,
per-input timeout 20seconds and RSS limit 2048MiB applied; runtime input max 34bytes,
diagnostic max 131072bytes. No findings in either batch.

| Target | Seeds supplied/loaded | Initial batch | Final batch |
| --- | --- | --- | --- |
| original_registry | 24 files / 24 loaded, 20 retained initial corpus | 4096 runs,404 s,605Mb reported RSS; cov 4981/ft 12759 | 4096 runs,322 s,607Mb; cov 4976/ft 12948;310 corpus entries/ 7045 bytes |
| diagnostic_format | 12 files / 11 nonempty loaded | 4096 runs,1 s,183Mb; cov 854/ft 1687 | 4096 runs,0 whole seconds reported,178Mb; cov 854/ft 1687;96 entries/ 1436 KiB |

The zero-second report is the tool's whole-second elapsed resolution, not zero
executions. Coverage counters are tool observations, not exhaustive branch proof.
The initial runtime batch's generated corpus is 319 entries/ 7173 bytes; both batches
and all outliers remain reported. Runtime requests use bounded dual-instance
replay, invalid IDs, stale handles, guarded states, damage/removal and diagnostics.
Diagnostic inputs include independent v20/v21 streams, malformed framing and
bounded mutations inside a valid stream. Nested opaque payloads are not a world
restoration parser. The fresh pre-merge M3f6 runtime-identity campaign was separate
and is not counted as M3f7 fuzz coverage.

RSS does not prove allocation counts or leak freedom.

## Unsupported work and next prerequisite

Spectre/Shotgun Guy, real players, generalized infighting, Fast/Nightmare/respawn,
resurrection, dynamic sectors, general projectiles, rendering/Vulkan, PK3/ZScript
and wider capacities remain excluded. Representing source identities does not
establish those behaviors. The next narrow recommendation is an independently
validated context/target-lifetime ownership contract before any real player or
additional actor admission. A separate evidence-storage audit can investigate
reuse/compression without changing historical files or Git history.
