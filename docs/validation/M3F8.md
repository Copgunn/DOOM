## Implemented boundary

An exclusive generative ExecutionContext uses invariant ContextActor lifetime
brands over existing ActorId values. Tokens cannot escape or cross scopes; every
access still checks generation and current definition. Explicit local admission
checks expected versus actual definition, not foreign raw provenance. Actor data
is copied for observation. No persistent context counter, duplicated identity,
second actor store, scheduler, global target sweep or new allocation is introduced
by opening/querying a scope. Allocation counts were not instrumented.

Derived availability separates live storage/corpses, pending removal, most recent
retirement, stale generations, unissued vacancy, zero generation and unallocated
slots. Generation exhaustion never wraps. Target observation delegates to the
shared definition-role guard; acquisition, replacement/clear, damage,
perception repair, state entry, spawn and stepping reuse current services. A body
may retain an incompatible damage-source reference without authorizing target
acquisition or body AI. Each operation retains atomicity; the callback is not an
aggregate transaction. Actor and geometry bounds, execution profile and DSIM20/21
bytes/schema identifiers remain unchanged.
