## Implemented boundary

`Simulation::advance` owns the former stepping body, returning unit without
Snapshot capture. `step` delegates, then captures once. The checked-Demon private
core also returns unit; `ExecutionContext::advance` delegates to the same owner,
including through GameInstance. All event recording and transaction plans remain.
`run_commands`, public Snapshot structures, encoding, digests, first-difference
behavior, profiles, original IDs and DSIM-v20/v21 interpretation are unchanged.
There is no unchecked execution mode, release rollback switch, new actor field,
second engine, capacity increase, dependency or unsafe Rust.

## Rust API and safety observations

- Full snapshots and canonical bytes match over Profiles1–20 and OriginalDemon,
  including command streams, state actions, pending/last events and RNG fields.
- The test-only thread-local capture hook observes zero captures from advance on
  success, pause or error; step captures once on success/pause and none on error.
  GameInstance/context delegation is also checked. No hook exists in production.
- Pause remains earlier than buttons and tic overflow; invalid buttons/overflow
  preserve complete state. Both RNG streams wrap without diagnostic draws.
- Scoped/qualified references retain their ownership and incarnation guards;
  target rejection, retirement and lowest-slot generation reuse remain unchanged.
- Staged actor/RNG/statistics/binding mutations cannot alter the source instance
  before commit. Existing late-failure rollback checks run through the same core.
- `run_commands` still collects the historical snapshots. Repeated explicit
  diagnostic reads do not alter commands, state, events, scheduling or RNG.

Six API unit tests, one private staging test, three ownership policy tests and
one reused-reference test add eleven tests. Snapshot equivalence is a Rust API
refinement property; C fields, independent bytes, schema policy and lifetime
safety remain distinct evidence families.

`ASAN_OPTIONS=detect_leaks=0` applied to every campaign and source sanitizer check.

allocator request counts are also not leak detection. Bounded campaigns are not
exhaustive. The unchanged original-C metadata, canonical Demon and ownership
observers separately passed supported ASan/UBSan and strict-arithmetic checks.


## Preservation and remaining scope

All165 original upstream blobs and6030 historical protected paths remain
byte-identical. Both lockfiles, source attribution, GPL-2.0-only manifests,
ignored asset tests, original tools/fixtures and archives are preserved. The
repository remains public; no unrelated branches/history, private implementation
or commercial assets are accessed or changed. Documentation checks currently
resolve75 Markdown files /893 relative links /99 anchors and verify20 exact
archives. Final link/preservation checks are repeated at delivery.

Real players, additional species, generalized infighting, raise/respawn, dynamic
sectors, broader projectile systems, rendering/Vulkan, PK3/ZScript, networking and
save restoration remain unsupported. Production panic-path review and historical
evidence storage remain separate maintenance priorities. The recommended next
gameplay slice is original MT_PLAYER body/mo/attacker ownership and independently
observed damage/death lifecycle, not another general identity abstraction.
