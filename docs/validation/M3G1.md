## Implemented boundary

`Simulation::advance` owns the former stepping body, returning unit without
Snapshot capture. `step` delegates, then captures once. The checked-Demon private
core also returns unit; `ExecutionContext::advance` delegates to the same owner,
including through GameInstance. All event recording and transaction plans remain.
`run_commands`, public Snapshot structures, encoding, digests, first-difference
behavior, profiles, original IDs and DSIM-v20/v21 interpretation are unchanged.
There is no unchecked execution mode, release rollback switch, new actor field,
second engine, capacity increase, dependency or unsafe Rust.

## Rust API and safety observations

- Full snapshots and canonical bytes match over Profiles 1–20 and OriginalDemon,
  including command streams, state actions, pending/last events and RNG fields.
- The test-only thread-local capture hook observes zero captures from advance on
  success, pause or error; step captures once on success/pause and none on error.
  GameInstance/context delegation is also checked. No hook exists in production.
- Pause remains earlier than buttons and tic overflow; invalid buttons/overflow
  preserve complete state. Both RNG streams wrap without diagnostic draws.
- Scoped/qualified references retain their ownership and incarnation guards;
  target rejection, retirement and lowest-slot generation reuse remain unchanged.
- Staged actor/RNG/statistics/binding mutations cannot alter the source instance
  before commit. Existing late-failure rollback checks run through the same core.
- `run_commands` still collects the historical snapshots. Repeated explicit
  diagnostic reads do not alter commands, state, events, scheduling or RNG.

Six API unit tests, one private staging test, three ownership policy tests and
one reused-reference test add eleven tests. Snapshot equivalence is a Rust API
refinement property; C fields, independent bytes, schema policy and lifetime
safety remain distinct evidence families.

## Actual allocation requests

Separate instrumented processes use the Linux/glibc host interposer, not a Rust
allocator modification or engine dependency. Zero-control intervals measured zero
requests; the positive Rust Vec control measured one 4096-byte request and one free.
All three request samples per workload/mode are retained separately from timing/RSS
samples. They match between step and advance+snapshot. Counted bytes sum successful
requested allocation sizes and full successful realloc sizes, not net live heap,
allocator-internal work, direct mappings, other threads or leak coverage.

| Small20 /100 calls | Allocation calls | Realloc requests | Cumulative requested bytes |
| --- | ---: | ---: | ---: |
| step | 374,663 | 27,622 | 15,643,606 |
| advance | 321,139 | 233 | 12,283,278 |
| advance_snapshot | 374,663 | 27,622 | 15,643,606 |
| capture | 52,800 | 26,500 | 3,308,900 |
| encode | 100 | 1,500 | 26,214,000 |

Advance avoids all full Snapshot construction and its names/values/event-payload
serialization. It still performs substantial gameplay/preflight/staging requests.
In this measured small20 stream the removed capture work accounts for 53,524 fewer
allocation calls and 27,389 fewer realloc requests per 100 updates. Frozen capture
and encoding have different state histories and are not the exact difference.
No allocation-free simulation or universal memory reduction is claimed.

## Transaction findings

The private release-test instrument measures 100 calls on each frozen INITIAL
workload state; all three process samples remain in the raw record. Its whole
test-process RSS is shared by the 15 intervals per process, includes the harness,
and is not a separate per-component heap/RSS measurement.

| Workload | Preflight median ms /100 | Staging median ms /100 | Preflight allocations /100 | Staging requested bytes /100 |
| --- | ---: | ---: | ---: | ---: |
| small_control /20 | 10.044 | 0.025 | 295,300 | 206,400 |
| four_owners /20 | 38.618 | 0.027 | 1,064,500 | 268,800 |
| high_cell_demon /20 | 10.728 | 0.022 | 295,300 | 206,400 |
| canonical_small /original | 9.718 | 0.026 | 289,300 | 206,400 |
| actor_capacity /original | 100.786 | 0.175 | 3,004,200 | 1,433,600 |

Staging made exactly two requests per plan: logical actor slots and spatial
capacity. In this compiler/target Slot<Actor> occupies 208 bytes and ActorId 16 bytes.
The five-slot small workload copies 1040 actor bytes and 80 spatial bytes while
reserving 1024 spatial bytes. At 64 slots those values are 13312/1024/1024 bytes.
Vacant logical slots also copy; geometry, immutable definitions/cache, sectors,
roster and sound targets remain borrowed. This is not a full-world clone.

The separately measured actor_preflight timer made no requests in these INITIAL
states because no actor's next-state demand was due. It can allocate at state
boundaries; this observation does not make that service allocation-free.
Repeated reachable-definition/state validation and its graph sets/vectors are a
substantial measured preflight cost. Staging is much smaller in these samples,
so deleting rollback is neither justified by cost nor safe: late checked sight/
work errors still occur before commit. All transactions are retained unchanged.

Future performance work may investigate immutable validated-definition caching
and reusable transient scratch, with separate proofs for dynamic state/role
checks, failed operations, late errors and exact events/RNG. No such optimization
or unchecked in-place execution is implemented here. CI enforces structural
capture/request checks and successful advisory benchmark execution, not timing
thresholds on shared runners.
