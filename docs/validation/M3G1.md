## Initial baseline, before runtime edits

The unchanged post-M3f9 tree was measured with Rust 1.99.1 on Linux x86_64.
Five historical tools each ran their established three separate release-process
samples. [Raw samples and provenance](m3g1-performance.json) retain compiler,
clean measured commit/tree and tool fingerprints. No timing thresholds apply.

| Historical update workload | Median ms / 100 updates | Median peak RSS KiB |
| --- | ---: | ---: |
| Small Profile17 | 13.168 | 3524 |
| Small Profile20 | 13.470 | 3500 |
| Typed lifecycle20 | 22.865 | 4008 |
| Four owners20 | 60.064 | 4388 |
| Wide geometry20 | 23.272 | 4564 |
| Sight DAG20 | 13.446 | 3684 |
| Line table20 | 13.546 | 4260 |
| Typed high-grid20 | 23.066 | 6344 |

These timers include scripted external operations and returned Snapshot capture.
The historical snapshot100_us includes capture AND encoding, not either cost
alone. Different rows are different workloads. Peak RSS includes setup, allocator,
observations and final checks; it is not isolated actor memory or live heap.
No CPU/frequency/shared-host isolation or universal speed claim is available.

At this investigation checkpoint, implementation and final-source checks have
not run. Subsequent sections will record actual results rather than planned passes.
