## Coordinated implementation

1. Source-first checkpoint freezes genuine original observations, components and
   independent DSIM26 fixtures before matching Rust gameplay.
2. Animated actor admission reuses map spawn, original descriptor state clocks,
   actor/thinker order and bounded role validation. Old policy9 cannot admit armor.
3. Shared contacts implement GiveArmor points thresholds and existing ordered
   message/removal/bonus/sound work, with no second pickup owner or collision loop.
4. Shared DamagePlan computes the current optional armor consequence once.
   DamageRequest remains raw for physical thrust; effective damage supplies player
   and signed mobj health, damagecount, tactile and death/pain decisions. Ignored
   damage bypasses armor. Autonomous SARG damage uses that same service.
5. The existing bounded transaction stages armor with player/weapon/actor state,
   spatial order, RNG, sound, statistics and events. No new allocator, scheduler,
   health mirror, unsafe Rust, full-world tic clone or implicit Snapshot exists.

The only persistent gameplay addition is an optional two-scalar armor record on
existing PlayerRuntime, selected only by PlayerDemonArmorV1. Actor records keep
actual original type/state/sprite/frame IDs. DSIM26 is required for those new
persistent player values and grant/absorption observations;20–25 remain unchanged.

## Rust safety and representation

Focused checks distinguish source comparisons from private safety fault setup.
They cover original policy isolation, typed armor domains, invalid actor animation
records, missing/stale/pending player ownership, unsupported controls/drops,
foreign instances, item retirement/effect slot reuse, malformed DSIM26 fields and
events, paused state, deterministic replay and complete step/advance equality.

damage is60/40/30. Invalid raw travel still rejects despite armor protection.

The existing late-error latch proves rollback after actual armor absorption,
depletion, thrust and death; artificial range-valid bonus state forces failure
after real grants/removal and prior commands. These are Rust safety policies,
not additional C gameplay. Map batches preflight every selected THING before RNG;
a later unsupported THING or capacity error preserves the whole batch. There is
no fabricated public late-failure branch after infallible preflighted spawning.

## Unsupported and next gameplay step

No bonuses, powers, cheats, Baby scaling, special sectors, telefrag system, new
weapons/monsters, respawn, multiplayer, full player/death thinkers, airborne or
dynamic geometry, rendering or savegame restoration is admitted. C pointer
lifetime behavior is not Rust generation safety. Shared-host timings and bounded
fuzzing are not universal performance or exhaustive correctness guarantees.

The next small gameplay candidate is source-validated health and armor bonuses:
actual animated actors,200-point caps and pickup ordering using the same stores,
contacts, damage and transaction services. Broad identity/ownership redesign is
not needed to pursue that separately authorized slice. Existing panic paths,
unnamed flags, repeated preflight allocations, transaction copying and reference
storage growth remain the roadmap's measured maintenance priorities.
