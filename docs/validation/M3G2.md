## Implemented gameplay boundary

One actual MT_PLAYER0 owns source states149–153/156–173 through the existing actor
store and shared damage/thinker services. PlayerSlot0 binds a full generational mo,
not a raw slot or synthetic body. Source health clamp, attacker assignment,
damagecount, pain, normal/extreme death, frags, sole-player kill credit, immediate
player nonsolidity and retained allocated corpses are admitted. Weapon lowering
and tactile requests are observed service boundaries, not presentation/weapon
execution. Unlisted body context excludes PlayerThink/DeathThink and automatic
roster/AI. Direct no-inflictor damage may use a live Demon between tics; it must
be killed/marked before traversal. Corpse sources and dying Demon actions execute.
Physical inflictors, controls, inventory/powers/armor, camera and respawn reject.

The optional small player record joins the existing checked actor transaction.
No per-actor identity mirror, new owner/scheduler/combat engine, capacity change,
unsafe Rust, dependency or implicit Snapshot is introduced. Death retains mo and
attacker; retirement/reuse leaves opaque generations which cannot redirect.
Historical profiles and v20/v21 remain separate, immutable contracts. New v22
represents genuinely new source player observations through an explicit reader.

one independent reference test pass. One additional compile-fail example enforces
