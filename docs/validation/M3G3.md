## Implemented boundary

PlayerBodyKnockbackV1 uses canonical MT_PLAYER=0, the existing source player/mo
record and original states 149–153/156–173. Existing LifeHost damage applies physical
thrust before player fields and signed mobj health. The shared thinker/movement
services execute subsequent grounded XY, friction, axis-wall slide/stairstep,
RUN-to-PLAY stopping and moving corpses. There is no second actor store, damage
engine, scheduler or player-specific stepping loop.

The new immutable capability is stored once beside source player state; no actor
identity/health mirror is added. Checked source and inflictor remain distinct.
Flat floor 0 / ceiling 128, axis-aligned one-sided walls, zero commands and the forward
travel envelope define support. Physical hits require a dying/corpse Demon owner
closure before momentum is committed. Existing stationary policy 2, native/canonical
identity boundaries, ownership/provenance and all previous capacities remain.

## Rust policy and API observations

Twelve integration policy tests and three private transaction/capture tests pass,
separately from the independent C reference test. They cover explicit capabilities,
unsupported geometry/settings/roles, source/inflictor generations and pending/
retired/reused references, foreign game instances, checked travel boundaries,
large/invalid damage, direct physics/state rejection, zero damage, retained moving
corpses, executable thinker admission and full late-error rollback. Exact positive
and negative travel boundaries accept while one-bit violations reject atomically;
accepted hits remain steppable through 100 updates. Existing ±994 spawn boundaries
still step and reject unsupported new hits without consuming RNG/events.

All 812 new scripted tics also compare complete step output with advance followed
by snapshot, including ordered events. A private capture hook observes zero
implicit captures for moving-player advance, pause or rejection, and one for step.
Existing compile-fail scope/provenance tests continue to apply to the unchanged
ownership types. Decoder tests preserve old v20/v21 entry points and v22 policy 2
while validating policy 3/context pairing and bounded malformed input rejection.

## Unsupported behavior and next gameplay boundary

Controls, PlayerThink/DeathThink, active roster/automatic Demon attacks, weapons,
projectiles, inventory/armor/powers/cheats, airborne player movement, angled/two-sided
walls, steps/dropoffs, dynamic sectors, camera, respawn and multiplayer remain
unsupported. C accepts some inputs rejected by conservative Rust admission; those
are safety restrictions, not proven C equivalence. No full player physics/gameplay
or vanilla demo claim follows from these bounded comparisons.

Next investigate bounded original P_MovePlayer command execution and its source
reaction-time/PlayerThink scheduling prerequisites. Keep view, weapon, active
roster/acquisition and respawn admission separate until independently executable.
Retain roadmap priorities for panic paths/named constants, evidence growth and
measured preflight/transaction allocation costs.
