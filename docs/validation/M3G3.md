## Implemented boundary

PlayerBodyKnockbackV1 uses canonical MT_PLAYER0, the existing source player/mo
record and original states149–153/156–173. Existing LifeHost damage applies physical
thrust before player fields and signed mobj health. The shared thinker/movement
services execute subsequent grounded XY, friction, axis-wall slide/stairstep,
RUN-to-PLAY stopping and moving corpses. There is no second actor store, damage
engine, scheduler or player-specific stepping loop.

The new immutable capability is stored once beside source player state; no actor
identity/health mirror is added. Checked source and inflictor remain distinct.
Flat floor0/ceiling128, axis-aligned one-sided walls, zero commands and the forward
travel envelope define support. Physical hits require a dying/corpse Demon owner
closure before momentum is committed. Existing stationary policy2, native/canonical
identity boundaries, ownership/provenance and all previous capacities remain.

## Unsupported behavior and next gameplay boundary

Controls, PlayerThink/DeathThink, active roster/automatic Demon attacks, weapons,
projectiles, inventory/armor/powers/cheats, airborne player movement, angled/two-sided
walls, steps/dropoffs, dynamic sectors, camera, respawn and multiplayer remain
unsupported. C accepts some inputs rejected by conservative Rust admission; those
are safety restrictions, not proven C equivalence. No full player physics/gameplay
or vanilla demo claim follows from these bounded comparisons.
