## Implemented gameplay boundary

PlayerDemonMeleeV1 composes one genuine MT_PLAYER=0 and at most one map-THING
MT_SERGEANT=12 with the fixed active roster `[true,false,false,false]`. Player
commands and reaction gating precede the existing thinker pass. Shared visual
search, wake-state entry and pursuit now reach original SARG melee selection.
The earlier PlayerDemonAcquisitionV1 retains its transactional melee rejection.
No actor capacities, historical policies, ownership types or scheduler change.

Selection enters S_SARG_ATK1=485, followed by ATK2=486 and ATK3=487, each eight
tics. FaceTarget runs on the first two entries; SargAttack runs on ATK3 entry,
16 thinker tics after selection. It faces the current target and rechecks current
range/sight before drawing `((P_Random()%10)+1)*4`. A moved-out-of-range target
therefore receives neither damage nor the successful-hit RNG draw. An absent
target returns before facing/range/RNG. A dead allocated target can still pass
the range check and consume the attack draw, followed by ignored damage; these
are different source branches.

The attack reads current staged health, position and target after earlier
thinker actions. It uses the existing DamageRequest, DamagePlan and LifeHost
damage application; the Demon is separately recorded as source and inflictor.
The existing checked physical-impulse proof is shared with direct player damage.
No future RNG value or successful hit is predicted. Live Demon thinking remains
admitted on subsequent tics, including after nonlethal and lethal hits. Player
health clamps at zero while mobj health stays signed. Pain, reaction reset,
attacker/target retention, death, corpse flags and subsequent grounded momentum
use existing services. Death retains the allocated, active and owned body; it
does not implement respawn, body retirement or P_DeathThink.

The transient action selector carries the existing execution capability, not a
second persistent policy or player record. There is no new actor/Simulation
storage field, actor store, combat engine, movement loop, RNG or lifetime manager.
Late failures discard the existing bounded transaction, including earlier player
commands, actual attack RNG, damage, impulse, state actions, statistics and events.
Diagnostic-free advance still uses the same execution core as step.

source comparison. They cover current canonical definitions and body ownership,
wrong/stale/foreign/pending/reused references, missing player, unsupported flags,
health consistency, exact delayed attack, miss/no-draw, dead-target ignored damage,
reaction reset, source/inflictor identity, live-Demon continuation, corpse and
attacker retention, schema rejection and the historical no-melee boundary.

Private tests inject failure after actual nonlethal and lethal staged damage and
compare complete snapshots. A current-health test applies an earlier staged hit

## Unsupported behavior and next gameplay step

This is bounded grounded player-versus-one-Demon combat in existing static
geometry. Full PlayerThink/DeathThink, camera, weapons, inventory, armor/powers,
cheats, respawn, multiplayer, additional monsters, generalized infighting,
dynamic geometry, Fast/Nightmare and resurrection remain unsupported. Source
pointer behavior is not Rust handle safety. New public error paths are checked;
historical production panic paths, repeated preflight/transaction allocation
costs and reference-data growth remain maintenance work with acceptance criteria
in [ROADMAP](../ROADMAP.md#focused-maintenance-acceptance-criteria).

The next narrow gameplay step is source-validated genuine-player pistol firing,
minimal ammo/cadence and the existing Demon's damage/pain/death and supported
retaliation, using shared services. It is a recommendation, not implemented here.
