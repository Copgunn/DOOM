## Implemented boundary

The separately selected PlayerDemonPistolV1 composes one genuine MT_PLAYER0,
optional map-THING MT_SERGEANT12, fixed active player0, grounded commands and
existing autonomous AI/melee with original pistol setup, psprites, ammo/refire,
autoaim/hitscan, real Puff/Blood thinkers, one-sector noise, shared damage,
Demon pain/death/retaliation and player kill credit. One authoritative player,
actor owner, RNG, thinker pass and bounded transaction remain. The transient
WeaponPlayer adapter returns only dynamic weapon fields; it does not persist
another player identity, health or lifetime.

DSIM23 is justified by new persistent pistol observations. Historical20/21/22,
synthetic weapons, prior capabilities and fixtures remain unchanged. Shared
state-entry metadata is borrowed rather than cloning its String; source timers
remain canonical. Source64-cell collection is newly admitted only here, while
historical trace APIs keep endpoint rejection. Death lowers only the owned
player's weapon; Demon death cannot lower the player's pistol.

14-tic held cadence, release/repress, flash/light, fallback aim without turning,
beyond-aim-range hits, wall puffs, ambush/noise and moving-player shots are compared.
No injected damage simulates a bullet hit in the autonomous encounters.

The driver is a declared command/reaction/CalcHeight/MovePsprites stage before
original thinkers, with only MovePsprites after death. It is not full Ticker,
PlayerThink or DeathThink. View/camera fields are excluded; grounded height makes
reverse-thrust RNG unreachable. Source retirement uses the inherited quarantine,
not freed-pointer access or C allocator equivalence. Invalid handle, foreign
instance, rollback and unsupported continuation are Rust safety policy.

## Matched performance and memory

Measurements use Rust 1.99.1 (58cf8f9c3), Linux x86_64/glibc 2.41 and identical release
settings and inputs. Each group has three separate timing/RSS processes and three
separate allocation-instrumented processes. Tests, builds and fuzzing did not run
concurrently with timing. The unchanged interposer controls observe zero requests
and one 4,096-byte request. Shared-host CPU/frequency/allocator isolation is absent.

All 127 matched production/diagnostic group digests match. Of their allocation
sample arrays, 125 match exactly. The two historical weapon groups each make 110
fewer allocation requests and request 1,074 fewer cumulative bytes per 100 calls
after psprite state entry borrows metadata instead of cloning its state-name
String. Reallocations match. This measured reduction is not an allocation-free or
general speedup claim. Five additional frozen legacy matrices and 45 transaction
component observations remain separate from evolving update measurements.

## Remaining gameplay boundary

Other weapons, switching/pickups, powers/armor/cheats, respawn, multiplayer, full
player thinkers/view, general sound propagation, additional monsters, infighting,
dynamic sectors, general airborne/angled/two-sided movement and rendering remain
excluded. Empty-ammo fist continuation rejects atomically. The next narrowly
scoped gameplay recommendation is independently validated original fist fallback
and bounded A_Punch against the same Demon through shared services.
