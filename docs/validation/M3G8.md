All five work packages execute in one bounded canonical player/Demon world:
empty-ammo fallback, unpowered fists, manual switching, shotgun and chaingun.
The [support contract](../COMPATIBILITY.md#original-player-weapon-expansion) is the
authority for accepted inputs; exact review commits and CI belong to GitHub.

contract. Before Rust runtime changes, the new compiled-C observer generated
27 scenarios / 5,664 scripted tics / 913 selected captures. Normal, strict
arithmetic and ASan/UBSan executions matched byte-for-byte. Address checks used
`ASAN_OPTIONS=detect_leaks=0`; no leak-detection claim is made.

The independently specified DSIM24 projection contains 12 full-byte fixtures,
5,691 event frames and 78,174 ordered event payload fields. Source observations
include 132 fist attacks, 19 pistol bullets, 98 shotgun pellets and 98 chaingun

[source](../../tests/reference/m3g8_provenance.json) and

At that initial source-only checkpoint, runtime implementation had not started.
The completed integration and observed validation are recorded below.

## Safety and stepping

Focused Rust policies verify invalid setup/ownership/weapon fields, unsupported
buttons and slots, stale/reused/wrong-definition bodies and foreign instances.
A deliberately exhausted effect capacity fails after earlier shotgun pellets
have already changed staged health. Separate failures after all seven pellets,
a lethal burst with kill credit/corpse fields, and immediate chaingun fire before
noise discard the entire transaction. Full snapshots prove preservation of ammo,
psprites, health, references, RNG, statistics, spatial/thinker order, events and tic.
Malformed DSIM24 fields reject; historical readers/policies keep their meanings.

Successful, dead, paused and rejected calls compare step against advance followed
by explicit snapshot. Structural capture counters verify advance creates no
implicit Snapshot. This does not imply allocation-free gameplay.

C trace in1,372,656 bytes and the2,031,665-byte independent event stream in258,939
bytes. Fifteen uniquely useful complete fixtures remain directly inspectable.
The bounded standard-library Python codec and safe test-only Rust decoder share
explicit literal/overlap vectors and malformed-input checks. This storage choice
is confined to new test evidence; no historical data migration, dependency, LFS
or external archive was introduced. Packed/unpacked digests and regeneration
preserve source provenance. Different scenario families are not normalized
performance or coverage-density comparisons.

## Performance and allocations

Measurements use Rust 1.99.1 (58cf8f9c3), LLVM 23.1.1, Linux/glibc on the same host.
The visible affinity contains five logical CPUs with a four-CPU cgroup quota and
16GiB memory limit. There is no CPU isolation or host-frequency control. Source,
tests and fuzz campaigns were stopped before timing. Each series retains three
separate timing/RSS processes and three separate allocation-probe processes.
The enabled allocation probe observed zero calls in its empty control and one
4,096-byte request in its positive control. Source parsing, setup/warmup and explicit final snapshots are
outside timing/counters, but remain part of whole-process peak RSS.

The fresh verified merged-master baseline was reused, with identical compiler,
maps, commands and unchanged measurement tools. All 157 matched groups retain
identical digests and all three allocation sample arrays, including calls,
reallocations, requested bytes, frees and failures. The historical state-name
clone removal remains intact. Five legacy matrices and45 transaction-component
samples per side are retained as well.

## Preservation, review and remaining scope

All 165 upstream files match the original authority byte-for-byte. All 6,320
protected historical paths,20 exact documentation archives, older DSIM formats,
tool paths, fixtures and both ignored asset tests remain intact. The repository
remains public and GPL-2.0-only, with original attribution and workspace licensing
preserved. No private source, commercial assets, incompatible code, framework,
force-push, history rewrite or unrelated branch deletion was used.

Documentation links/anchors and archive digests are checked, alongside a human
readability/scope review of current guides. The pull request records exact final
feature/synthetic trees, parents and Linux/Windows/native Intel macOS/Rust 1.85 CI.
It must remain open and unmerged with auto-merge disabled.

Full PlayerThink/DeathThink, camera, armor/powers, Berserk, other weapons, pickups,
respawn, multiplayer, additional monsters, infighting, arbitrary geometry,
generalized sector sound, dynamic sectors and rendering remain excluded.
Source composition, diagnostic policy and Rust ownership/rollback protections
remain separate claims. The next gameplay recommendation is a small source-backed
clip/shell and health-pickup slice through the existing player/inventory/touch
services; it is not part of this milestone.
