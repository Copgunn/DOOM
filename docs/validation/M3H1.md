## Review notes and follow-ups

An independent reviewer read only the `crates/` diff from `7122e40` and the
original `info.c`, `p_enemy.c`, `p_inter.c`, `p_mobj.c` and `p_map.c`. It verified
attack/refire/missile-range order, retargeting, P_KillMobj ordering and drops,
registry closures, the roster cap, rollback latching, historical gating and the
DSIM28 reader, and reported two verified bugs, both fixed in `5857c3a`:

- The direct state-entry guard applied only to the Demon, so a live former human
  could be entered into its death or pain state through the public API. The guard
  now covers every roster monster (regression test added).
- `P_CheckMissileRange`, first reached by former humans, used the historical
  infallible sight query inside the checked world. It now uses the bounded
  fallible query whenever an operation control exists; all source replays are
  unchanged.

Of its suspicions, the overwritten latched error and the missing former-human
closure proof in `OriginalExecutionRegistry::admit` were also fixed. The
remaining one stays a follow-up: former humans have no per-tic flag/lifecycle
consistency check comparable to the Demon's `lifecycle_owner`. Post-tic travel
proofs and API guards cover them.
