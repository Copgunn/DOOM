### The M3h1 bonus `sixteen` regression

M3h1 recorded +9–11% medians with equal minimums and could not separate that from
noise. Measured again here, alone, across `7122e40` and `d997cf9`:

| Measure | 7122e40 | d997cf9 | Δ |
| --- | ---: | ---: | ---: |
| 101 interleaved pairs, median ms | 1.788 | 1.889 | +5.6% |
| 101 interleaved pairs, minimum ms | 1.713 | 1.803 | +5.3% |
| Instructions over a 20,000-tic scratch run | 4.865 G | 5.101 G | +4.8% |

**It is a real, repeatable cost, not host noise,** and the earlier "equal minimums"
observation did not reproduce. Instruction sampling over the lengthened run
(two runs each, about 17,000 samples per build) attributes it: +583 of the +920 extra
samples land in the sound-array closure of `OriginalActorType::descriptor`, which
exists as a separate symbol only in `d997cf9`, because that closure stopped being
inlined. `world_pickups::validate_definition` reaches `descriptor` for every item on
every tic's preflight. Smaller additions are in `monster_actor`, `validate_monster_type`
and `preflight_map_demons`. About 40% of samples in both builds are per-tic registry
revalidation, which is the larger opportunity. The lengthened run was a scratch edit
and is not committed. M3h2 made no fix for it.

## Independent review

A fresh reviewer read only the `crates/` diff from `d997cf9` and the original source,
without running anything. It reported no reachable panic, no source-order or RNG
divergence and no historical regression, and two verified low-severity bugs, both
fixed in `428f903` with regression tests:

- The DSIM29 live-fireball bound relied on field order, which the reader does not
  enforce. It now reads each slot.
- `check_multisector_position` answered a fireball with the non-missile rule, so a new
  fireball appeared blocked by its owner. It now uses the missile contact rule.

Its suspicions were carried into the review below.

## Second review

The owner requested a cloud `ultra` review of PR44. What returned on `80dd92d` described
itself as a **max-effort review, incomplete**: all finder angles ran, but its sweep phase
did not run and two verifiers had not reported. Those two then finished separately. **This
is not a completed cloud ultra review; the owner deferred that review, and the PR stays
in draft for it.**

Fixed in `ce401d1`, with regression tests where behavior changed:

- The 16-fireball cap froze ordinary unscripted runs: 2 of 64 seeds in a ±768 room and
  8 of 64 at ±984, with eight Imps. Retries could not clear it, and a 512-command sweep
  found no escape. The cap is now 24; with the fixed code 512 soak seeds across eight
  layouts gave 0 cap rejections and a peak of 19. This is a measured margin, not a proof.
- `validate_live_projectiles` accepted a malformed `pending_removal`, which could hide a
  live fireball.
- Removing the owner of a flying fireball returned Ok and then rejected each step. The
  verifier found this recoverable, not permanent; `mark_remove` now rejects it directly.
- A launch from an off-floor source could commit an unsteppable fireball (public API only).
- The visit-limit latch also changed older policies; it now applies only to this one.
- The new damage fuzz seeds were malformed, a test passed for the wrong reason, and the
  dispatch doc overclaimed.

Open, not fixed:

- **Permanent stall from the travel envelope.** A hit near a wall can exceed
  `|position| + 160M/3 <= 994`, and rollback restores the same hit. It reproduces in the
  ±768 room with map THINGs and commands only: seed 51 stuck after 655 commands, 0 of
  250,880 sampled inputs escaping, a sampled sweep and not a proof. Base `d997cf9` stalls
  the same way with hitscan alone (seeds 6 and 33), so it is pre-existing; fireballs reach it
  more easily. In soaks it stopped 4 of 128 seeds at ±768 and every seed at ±984 where the
  player stood near a wall. Some such states do have a narrow escape. Earlier compatibility
  text promising a safe zero-command continuation does not hold for this case. Replacing
  the envelope changes frozen contracts, so it is the recommended next milestone.
- **Walls past 994.** Admission allows them. A fireball crossing x=994 stopped every later
  tic in one room x∈[-300,1200]. That run was not repeated, because its scratch files were
  deleted during cleanup; the reading of `monsters.rs` supports it.
- **Cap and store rejections stay permanent if reached.** 24 is a margin, and 15 impact
  slots became 7 in the theoretical worst case. No soak covered a full item and drop budget.
- **Cleanups left for later:** the near-duplicate Imp and former-human policies, six
  hand-extended profile lists, repeated DSIM policy ladders, extra preflight passes and
  `actor_aim` reimplementing `approx_distance`.
